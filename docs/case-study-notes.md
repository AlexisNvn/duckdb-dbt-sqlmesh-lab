# Case-study evidence

The published snapshot in `analysis/case-study/` is copied from the verified
fixture suite `20260913T131941Z-c7705b34`, executed on 2026-09-13. Its report and
seven charts were generated by `analysis.generate`; source-results.json and
provenance.json retain the source bytes and SHA-256. run-metadata.json preserves
the machine, versions, input hashes and original local paths. These paths describe
the recording machine and are not required to read the report on another machine.

The three plan JSON files are copied directly from the SQLMesh scenario artifacts.
They establish scheduling decisions, not engine scan counts or measured CPU savings.
The runtime table is derived from execution_seconds in source-results.json with
three-decimal display rounding. No fixture measurement is a full-scale TLC result.

This small snapshot is deliberately tracked so GitHub readers can see the evidence
without running the project. General generated output and benchmark databases remain
ignored. To generate a new report from this exact input:

```sh
uv run --frozen python -m analysis.generate analysis/case-study/source-results.json --output-dir analysis/generated/reproduced-case-study
```

The source execution preceded the final README commit. Runtime values must never be
silently regenerated or represented as measurements of a later revision. Future
published results should use a new run ID and retain their own source artifacts.
